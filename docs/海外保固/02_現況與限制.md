## 3. 技術背景（工程端看就好，業務可跳過）

- 網站：Next.js，部署在 Vercel；程式庫在 GitHub，推上去會自動部署。
- 資料庫：Supabase（PostgreSQL）。**這個資料庫專案與另一個不相關的網站（iPad 選機）共用**，所以本網站只能新增名稱以 `warranty_` 開頭的資料表。
- 寫入方式：登錄資料由網站的**伺服器端**用密鑰寫入；瀏覽器不直接碰資料庫。公開訪客對登錄表完全沒有權限。
- 語言：中文與英文；海外頁預設英文。
- 相關程式位置：登錄表單 `components/WarrantyForm.tsx`；登錄 API `app/api/warranty/register/route.ts`；驗證與寫入 `lib/warranty.ts`；建表 SQL `docs/sql/001_warranty_init.sql`。

## 4. 資安與隔離規則（不可違反）

用一般人聽得懂的話說：

1. **這個網站跟公司 ERP 是兩個世界。** 網站拿不到 ERP 的資料、也沒有 ERP 的鑰匙。就算網站被攻擊，ERP 不會受影響。
2. **客人的資料只能被「自己」看到。** 網站任何地方都不能讓人瀏覽別人的登錄資料。查詢保固一定要有驗證。
3. **所有客人輸入的內容都不可信。** 例如有人可能在「問題描述」裡塞惡意內容，系統要當成純文字處理。
4. **寄信功能要防濫用。** 否則壞人可以用我們的網站大量寄垃圾信，導致寄信服務被封、客服信箱被灌爆。
5. **密鑰不寫進文件、不貼給 AI、不放進程式碼。** 只放在部署平台的環境變數裡。
6. **若將來要和 ERP 比對訂單**，只能由 ERP 主動送最少的結果過來，網站不能反過來連 ERP。

## 5. 個資注意事項（需要有人負責確認，不是法律意見）

登錄與案件會收集**姓名、Email、聯絡方式、購買資料**，屬於個人資料。海外客人所在地的法規可能不同（例如歐盟 GDPR、美國加州 CCPA、日本個資法等）。下列事項需由公司負責人或法務確認，對應 `04` 的 Q12：

- 要不要放**隱私權政策**連結，要不要請客人**勾選同意**
- 資料**保存多久**、客人要求刪除時怎麼處理
- 資料存放在**哪個地區**的伺服器（目前的資料庫區域需工程端確認）
- 寄信服務商也會經手客人的 Email，需要確認其條款

## 6. 已知限制與風險

- **舊網站與舊系統（WordPress、Johnny 的全球保固系統）**：資料是否匯入、何時切換尚未決定（Q13）。2027 年 1 月底關站前要完成。
- **登錄資料目前只能由工程端從資料庫直接查看**，業務與客服暫時沒有介面可用（Q16）。
- **保固規則未定**：沒有規則就算不出「保固到期日」，查詢保固功能的價值會大打折扣（Q2）。
- **海外訂單編號難以核對**：各通路（例如 Amazon）的訂單在不同系統，網站無法自動驗證真偽（Q5）。
