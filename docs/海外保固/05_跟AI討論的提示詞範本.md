# 跟 AI 討論的提示詞範本

直接複製貼上，把 `【】` 裡的字換成你的情況即可。

## 步驟 0：先餵資料

把這個資料夾的檔案交給你的 AI（`README.md`、`00`～`04` 都要）。能上傳檔案就上傳；不能的話，依序貼上。

## 步驟 1：開場提示詞

```
我是【公司名稱】的海外業務。我附上一個「海外保固與售後」的討論資料包，
請你先完整閱讀，特別是 00_給AI的上下文.md，並遵守裡面的守則。

讀完後，請用你自己的話回答三件事，確認你理解了：
1. 這個專案要做什麼（三句話以內）
2. 有哪些硬性限制是我們不能違反的
3. 04_待決定事項.md 裡「卡關」的題目有哪幾題

然後等我說「開始」，再從 Q1 開始一題一題跟我談。
```

## 步驟 2：逐題討論

```
開始。請談【Q1】。
請先用白話說明這題在決定什麼，再給我 2～3 個選項與各自的好壞，
最後告訴我你推薦哪個、為什麼。
不確定的地方請直接說「我不確定」，不要猜，也請告訴我該去問誰。
```

換下一題時：

```
這題的結論是：【你的決定】。請記下來，我們談下一題【Q2】。
```

## 步驟 3：站在客人角度演練（建議每個功能都做一次）

```
請你扮演一位【在美國的客人】，產品壞了想申請維修。
請你一步一步描述：你打開網站會看到什麼、每一步會填什麼、
哪裡可能搞不懂或卡住、送出後你會期待什麼。
然後告訴我流程有哪些漏洞。
```

可以換成其他情境：「客人輸入了錯的 Email」「客人忘了登錄編號」「客人其實沒登錄過」「有人想亂填垃圾資料」。

## 步驟 4：請 AI 檢查有沒有漏掉

```
根據我們已經決定的內容，請你檢查：
1. 有沒有前後矛盾的決定？
2. 有沒有哪個「卡關」題還沒決定、但會讓工程無法開工？
3. 有沒有哪個決定違反了 00_給AI的上下文.md 的硬性限制？
請列出來，不要自己改我的決定。
```

## 步驟 5：產出「決議摘要」交給工程端

```
請把我們已經決定的內容，整理成下面的格式。
還沒決定的題目請列在最後，不要替我決定。
```

### 決議摘要格式

```
# 海外保固決議摘要
日期：【YYYY-MM-DD】　討論人：【姓名】　使用的 AI：【名稱】

## 已決定
| 題 | 決定內容 | 理由（一句話） | 決定者 |
|---|---|---|---|
| Q1 | ... | ... | ... |

## 尚未決定（需要誰、什麼時候前給答案）
| 題 | 卡在哪 | 需要誰回答 | 期限 |
|---|---|---|---|

## 討論中新發現的問題或需求
- ...

## 我們對客人承諾的事（頁面上會寫的文字）
- ...
```

## 注意事項

- **不要貼真實客戶資料**（姓名、Email、訂單編號）。需要舉例時，用「test@example.com」之類的假資料。
- **不要貼任何密碼、金鑰、登入連結。**
- 如果 AI 說的內容和 `00_給AI的上下文.md` 的「已確認的事實」不一致，**以資料包為準**，並請 AI 說明它的依據。
- AI 提出的法律、個資規範相關說法，只能當作提醒，**必須由公司負責人或法務確認**。
- 結論要寫回 `04_待決定事項.md` 的「決定內容」，或交給工程端用決議摘要，口頭說過的不算數。
