# 需求與流程

來源：海外業務提供的架構圖。下面把它翻成每一步的白話流程。**標「待決定」的地方，對應 `04_待決定事項.md` 的題號。**

## 1. 整體架構

```
保固與售後
├─ A. 保固登錄
├─ B. 查詢保固
│   └─ 輸入登錄的 Email ─ 一鍵申請維修／聯絡售後 ─ 留下問題和聯絡方式 → 寄到客服信箱
└─ C. 申請維修／聯絡售後
    └─ 留下問題和聯絡方式 → 寄到客服信箱
```

三個功能都放在**海外頁**（英文為主）。B 和 C 最後走同一個「留下問題和聯絡方式」的表單；差別是 B 從查詢結果進來，客人的產品與保固資訊可以**自動帶入**，不用再填一次。

## 2. 客人會是誰、想做什麼

| 客人 | 情境 | 用哪個功能 |
|---|---|---|
| 剛買產品的客人 | 想確保日後有保固 | A 保固登錄 |
| 用了一陣子的客人 | 想確認還在不在保固內 | B 查詢保固 |
| 產品出問題的客人 | 想送修、想問問題 | B（若有登錄）或 C（沒登錄／不想查） |
| 沒登錄過的客人 | 買了很久才發現壞了 | C 申請維修／聯絡售後 |

## 3. 功能 A：保固登錄

| 步驟 | 客人看到／做什麼 | 系統做什麼 |
|---|---|---|
| 1 | 進入海外頁，點「Warranty registration」 | 顯示登錄表單（英文） |
| 2 | 填：姓名、Email、購買產品、購買通路、訂單編號、購買日期 | 即時檢查格式（Email 格式、日期不能是未來） |
| 3 | 按送出 | 寫入登錄資料，產生登錄編號 |
| 4 | 看到「登錄完成」與登錄編號，被提醒要保留編號 | — |

**待決定**：海外要不要多收「國家」「序號」（Q6）；通路清單海外版有哪些（Q6）；登錄後要不要寄確認信（Q10）；訂單編號要不要人工核對（Q5）；是否要同意隱私條款（Q12）。

**現況**：這個表單在程式裡已存在（目前台灣用），海外版需要調整欄位與通路清單。

## 4. 功能 B：查詢保固

| 步驟 | 客人看到／做什麼 | 系統做什麼 |
|---|---|---|
| 1 | 點「Check warranty」 | 顯示查詢頁 |
| 2 | 輸入**登錄時填的 Email**（是否還要加登錄編號，待決定 Q3） | 去找符合的登錄資料 |
| 3a | 找到：看到產品、購買日期、保固到期日、狀態 | 只顯示**這位客人自己的**資料（顯示哪些欄位見 Q4） |
| 3b | 找不到：看到「查無資料」與兩個出口：重新輸入、**改用 C 聯絡售後** | 不透露「這個 Email 有沒有登錄過」以外的資訊（細節見 Q3） |
| 4 | 在查詢結果上按「一鍵申請維修／聯絡售後」 | 帶著產品與登錄編號，進入功能 C 的表單 |

**重點**：
- 「登錄的 Email」是查詢的**鑰匙**，也是安全關鍵。若只輸入 Email 就能查，任何人知道別人的 Email 就能看到對方買了什麼。怎麼驗證是**最重要的待決定題（Q3）**。
- 保固到期日要有規則才算得出來（Q2）。規則沒定之前，這個欄位只能空著或手動填。

## 5. 功能 C：申請維修／聯絡售後

| 步驟 | 客人看到／做什麼 | 系統做什麼 |
|---|---|---|
| 1 | 點「Request repair / Contact support」（或從 B 一鍵進來） | 顯示表單；若從 B 進來，產品與登錄編號已自動帶入 |
| 2 | 填：問題描述、聯絡方式；視需要附產品、序號、國家、照片（欄位見 Q7） | 檢查必填、長度、格式 |
| 3 | 按送出 | ① 保存這筆案件（是否保存見 Q8）② 寄信到客服信箱 |
| 4 | 看到「已送出」，並知道多久會收到回覆（Q17）；若有案件編號也一併顯示 | 視 Q10 決定是否寄確認信給客人 |

**客服收到的信**至少要有：客人姓名、聯絡 Email（可直接回覆）、問題描述、產品、登錄編號（如果有）、國家、送出時間。

## 6. 怎麼算做完（驗收標準，草案）

**A 保固登錄**
- [ ] 客人在英文介面可完成登錄並拿到登錄編號
- [ ] 欄位漏填、Email 格式錯、日期是未來，都會被擋下並有英文提示
- [ ] 機器人亂填被擋住，且不會污染資料

**B 查詢保固**
- [ ] 正確的客人能查到自己的保固狀態
- [ ] 別人**無法**用猜的看到他人資料（至少要驗證通過才顯示）
- [ ] 查不到時，客人有明確的下一步（改用 C）
- [ ] 一鍵帶入產品資訊到 C 的表單

**C 申請維修／聯絡售後**
- [ ] 客人送出後，客服信箱收到完整的信，且能直接回覆給客人
- [ ] 即使寄信失敗，這筆案件不會憑空消失（見 Q8）
- [ ] 不能被拿來大量寄垃圾信（見 Q14）

**共通**
- [ ] 全程英文介面，手機上可用
- [ ] 不會在網站任何地方顯示他人的個資
- [ ] 不影響台灣頁與 ERP

## 7. 暫不處理（先不做，之後再議）

- 客人登入帳號、會員中心
- 維修進度追蹤頁（客人自己看維修到哪了）
- 線上付款、運費計算
- 多語言（先英文，其他語言見 Q11）
