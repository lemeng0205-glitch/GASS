# 海外保固頁面 × 全球服務中心：整合指南

**給誰看**：負責做「海外保固頁面」的開發者，以及他使用的 AI。請把整份文件交給 AI 一起讀。
**目標**：讓海外保固頁面長在全球服務中心裡面（同樣的外觀、同一個網址體系、共用國家／語言／類別／說明書資料），而不是另一個孤立的網站。

---

## 2. 不能違反的限制

1. **不碰 ERP**：不連 ERP 資料庫、不呼叫 ERP、不要求任何 ERP 金鑰。本站也沒有 ERP 的任何東西。
2. **不碰台灣頁**：台灣的功能與版面不能因為你的修改而改變。
3. **個資**：保固登錄／維修案件含姓名、Email 等個資。公開訪客不可直接讀寫資料表（RLS 全部鎖死，只有網站伺服器端能寫）；log 裡不要印出個資；查詢頁一律只回傳「該客人自己的資料」。
4. **資料表命名**：只新增 `warranty_` 開頭的新表，不改既有表的既有欄位；SQL 寫成可重複執行（`if not exists`），放在 `docs\sql\` 編號往後排（目前到 `011`），由專案負責人在 Supabase SQL Editor 執行。
5. **金鑰**：不要把任何金鑰、`.env` 內容貼進對話、文件或程式碼。需要新的環境變數，請列出名稱交給專案負責人設定。
6. **範圍**：「討論稿」第 5 節還有很多題**沒有決定**（客服信箱、保固期限、驗證方式、寄信服務、隱私條款…）。**不要自己替公司決定**；先做不依賴這些決定的部分，其餘列成問題清單回報。

## 3. 建議做法：做在這個專案裡（融合）

比起另一個獨立網站，直接放進本專案最省事，因為：樣式、語言切換、國家與說明書資料都已經有，不用另外串 API。

| 要做的事 | 怎麼做 |
|---|---|
| 新增頁面 | 在 `app/` 下新增路由，例如 `app/warranty/page.tsx`（海外保固入口）。版面可參考 `components/RegionPage.tsx`、`components/QuickLinks.tsx` |
| 接到網站導覽 | 首頁／國家頁的「保固登錄」卡片目前連到舊 WordPress：`lib/portalConfig.ts` 的 `WARRANTY_GLOBAL`。**頁面上線後，把它改成你的內部路徑**（例如 `/warranty`）；**現在先不要改** |
| 語言 | 站上介面只有 `zh`／`en` 兩種：文字用 `L10n = { zh, en }`（見 `lib/portalConfig.ts` 的 `COPY`），語言由 `getLang()`（`lib/serverLang.ts`）取得。海外頁預設英文 |
| 國家／語言／類別 | 直接用函式：`getCountries()`（`lib/countryDb.ts`）、`getLanguages()`（`lib/languageDb.ts`）、`getCategories()`（`lib/categoryDb.ts`）。不要再寫死一份清單 |
| 說明書 | 用 `catalogFor(國家, 語言)`（`lib/catalog.ts`）取得依類別分組的說明書清單；電子模板用 `templatesFor(國家)`（`lib/templates.ts`） |
| 保固登錄 | 台灣已有雛形：`components/WarrantyForm.tsx`、`app/register/page.tsx`、`app/api/warranty/register/`、`lib/warranty.ts`、`docs/sql/001_warranty_init.sql`。海外版是否沿用、要加哪些欄位（國家、序號），看討論稿 Q6 |
| 資料庫存取 | 伺服器端用 `lib/supabaseRest.ts`（`rest()`），只能在 Server Component／Route Handler 使用（`import 'server-only'`） |
| 安全標頭 | `next.config.mjs` 有嚴格 CSP（只放行自己與本站 Supabase 的圖片）。新增外部腳本（例如 Turnstile 真人驗證）需要同步放行，並說明原因 |

開發環境：`npm install`、`npm run dev`。⚠ 專案在 Google Drive 上，**`node_modules` 請在 Drive 以外的資料夾安裝與建置**（複製一份出去 build），否則會卡死。

## 4. 如果你的頁面必須是獨立網站：用公開唯讀 API

已經提供，不需要任何金鑰：

```
GET {本站網址}/api/public/v1/service-center
GET {本站網址}/api/public/v1/service-center?country=jp&ui=en
```

| 參數 | 說明 |
|---|---|
| `country` | 選填。國家代碼（`tw`、`intl`＝全部海外，或 `jp`、`de` 等；可用代碼看回傳的 `countries`）。有帶才會回傳該國的說明書與電子模板 |
| `ui` | 選填。`en`（預設）或 `zh`；影響類別名稱（`label`）與產品名稱的語言 |

回傳（`success: true` 時）：

```jsonc
{
  "success": true,
  "data": {
    "version": 1,
    "portal": "https://…",                       // 本站網址
    "countries":  [{ "code": "jp", "name": {"zh":"日本","en":"Japan"}, "languages": ["ja","en"], "page_url": "https://…/country/jp" }],
    "languages":  [{ "code": "ja", "label": "日本語" }],
    "categories": [{ "key": "keyboard", "name": {"zh":"鍵盤保護殼","en":"Keyboard cases"} }],
    "country": {                                  // 只有帶 country 才有
      "code": "jp", "name": {…}, "languages": ["ja","en"],
      "manual_groups": [{
        "key": "keyboard", "label": "Keyboard cases",
        "items": [{
          "slug": "hyperkeys", "name": "eiP HyperKeys Keyboard Case",
          "url": "https://…/m/hyperkeys?country=jp&lang=ja%2Cen",   // 說明書頁，請用新分頁開
          "image": "https://…png",                                    // 可能是 null
          "languages": [{ "label": "日本語", "url": "…" }, { "label": "English", "url": "…" }]
        }]
      }],
      "templates": [{ "title": "…", "format": "PDF", "size_bytes": 516000, "download_url": "https://…", "preview_image": null }]
    }
  }
}
```

使用規則：

- **唯讀**，只有 `GET`（與瀏覽器預檢 `OPTIONS`）；不含任何個資、不含保固登錄資料。
- **圖片網址 1 小時就會失效**（簽名連結）→ 不要把圖片網址存起來，每次渲染前重抓；API 本身有 5 分鐘快取。
- 找不到國家回 `404 { success:false, error:'unknown country' }`；伺服器錯誤回 `500`。
- 說明書頁與檔案**不能用 iframe 嵌入**（本站禁止被嵌入），請用連結開新分頁。
- 你的網站若有 CSP：`img-src` 要加本站網址與 `https://pzvthhadlaoslebbmvlw.supabase.co`；`connect-src` 要加本站網址。
- 要限制只有特定網站能呼叫：專案負責人可在本站設定環境變數 `PUBLIC_API_ORIGINS`（逗號分隔網域）；預設任何網站都能讀。
- 最小範例：

```js
const base = 'https://gass-puce.vercel.app'   // 暫時網域；正式網域確定後改這一行
const res = await fetch(`${base}/api/public/v1/service-center?country=jp&ui=en`)
const { success, data } = await res.json()
if (success) data.country.manual_groups.forEach(g => console.log(g.label, g.items.map(i => i.name)))
```

這支 API 只用來「讀」展示資料。**保固登錄、查詢保固、申請維修需要寫入資料庫，不能走這支 API**，必須做在本專案裡（第 3 節），因為那需要伺服器端資料庫權限與個資保護。

## 5. 外觀要融在一起

- 色彩變數（`app/globals.css` 的 `:root`）：`--bg:#f3f2ef`、`--card:#ffffff`、`--ink:#45423e`、`--soft:#7a756e`、`--rule:#e2ded7`、`--accent:#8c7f68`、`--accent-ink:#fbf8f2`、`--muted:#b9b4ac`。
- 現成樣式：玻璃卡片 `glass`／`glass-hover`、圓角 `rounded-2xl`、小字距標籤 `tracking-wider`。請沿用，不要另外引入 UI 框架。
- 國家頁標題、返回連結、頁尾：直接用 `components/RegionPage.tsx` 的版型，使用者在各頁之間才不會感覺換了網站。
- 手機優先（客人會用手機操作），英文版文字要通順自然。

## 6. 海外保固的業務規格：先讀討論稿

- `docs\海外保固\海外保固_討論稿.md`（三個功能：A 保固登錄、B 查詢保固、C 申請維修／聯絡售後；建議上線順序 C → A → B）
- `docs\海外保固\給AI的指示.md`（已確認的事實與回答守則）

重點提醒：Q1 客服信箱、Q2 保固期限、Q3 查詢驗證方式、Q7 維修表單欄位、Q9 寄信服務、Q12 隱私與個資，目前都是**未決定**。沒有答案前：

- 可以先做：版面、表單欄位檢查、案件存資料庫（先存再寄）、防濫用（隱藏欄位、次數限制）、英文文案草稿。
- 不要做：寫死客服信箱或保固年限、查詢頁只用 Email 就回傳資料（討論稿 L1，不建議）、任何未經確認的法律／隱私文字。
