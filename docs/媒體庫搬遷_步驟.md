# 媒體庫搬遷（ERP → 本網站資料庫）

**決定（2026-11-18）**：媒體庫的資料與檔案改放本網站的 Supabase 專案；維護人員仍在 ERP 後台上傳、覆蓋、下載。ERP **不持有**資料庫金鑰，改為用簽章呼叫本網站的管理 API。

## 結構

```
維護人員 → ERP 後台（權限、2FA 不變）
              ↓ ERP 伺服器端，HMAC 簽章
        本網站 /api/admin/media  ──→  warranty_media_* 資料表 + 私有 bucket warranty-media
                                          ↑
客人 → 本網站 /m/<編號>、/m/<編號>/f/<id>（只讀已上架檔案）
```

|---|---|---|

| 2 | 把 ERP 現有 21 份說明書搬過來（檔案、歷史版本、開啟次數） | ✅ 已搬（2026-11-18）：21 份、43 版、122.2MB，逐檔 SHA-256 核對 253 項全過 |
| 3 | ERP 端改呼叫管理 API（用開關控制，預設仍用舊的） | ✅ 程式已上線（ERP v1.5.0），**開關關閉**，行為不變 |
| 4 | 切換：設定 ERP 環境變數、保固網站說明書連結改指自己 | ✅ 已切換（2026-11-18）：ERP 舊連結全數轉址；保固網站 v0.13.0 連結改指自己。**待 ERP 後台實際操作驗證**（登入後上傳、覆蓋、下載、還原、刪除） |

階段 1 上線後，客人看到的一切都**不變**：`/m/` 在網站端查不到資料時只會顯示「找不到」，沒有人會連到它；管理 API 沒設憑證前完全關閉。

## 啟用步驟（階段 1，已完成）

1. **建表**：Supabase 專案（保固網站用的那個）→ SQL Editor → 貼上 `docs/sql/002_media.sql` 全部內容 → Run。最後會列出驗證結果，應看到 2 張表（`rls=true`）與 1 個 bucket（`public=false`）。只新增 `warranty_media_*` 與 bucket `warranty-media`，不動其他東西。
2. **管理憑證**：已產生並寫入本機 `樂萌全球保固網站/.env.local` 的 `PORTAL_ADMIN_SECRET`（64 字元，不在 git 裡）。請把**同一個值**貼到 Vercel 保固網站專案（`gass`）的環境變數 `PORTAL_ADMIN_SECRET`（Production），然後重新部署。**不要貼到聊天室或任何文件。**
3. 之後階段 3 才需要把同一個值貼到 ERP 專案。

## 憑證輪換

1. 產生新憑證。2. 網站：把舊值移到 `PORTAL_ADMIN_SECRET_PREV`，新值放 `PORTAL_ADMIN_SECRET`，部署。3. ERP：換成新值，部署。4. 確認正常後，刪除網站的 `PORTAL_ADMIN_SECRET_PREV`。

## 管理 API 規格（給 ERP 端實作用）

`POST /api/admin/media`，body 為 JSON，必帶 `op`；標頭 `x-admin-ts`（Unix 秒，10 碼）與 `x-admin-sig`（`HMAC-SHA256(secret, ts + "." + 原始 body)` 的十六進位小寫）。時間戳誤差超過 120 秒、簽章錯誤、沒設憑證，一律回 404。

| op | 參數 | 回傳 `data` |
|---|---|---|
| `list` | — | 文件陣列（含版本） |
| `upload_url` | `slug`、`lang`、`mime`、`size` | `{ path, token }`（瀏覽器直傳用） |
| `create` | `slug`、`lang`、`title`、`kind`、`sku`、`file`、`actor` | 新文件 |
| `add_version` | `id`、`file`、`actor` | 新版本（覆蓋） |
| `patch` | `id` + `title`／`kind`／`sku`／`is_published`／`slug`／`lang` | 更新後文件 |
| `delete` | `id` | `null` |
| `restore` | `id`、`version_id` | 更新後文件 |
| `download_url` | `id`、`version_id`（選填） | `{ url }`（60 秒、強制下載、原檔名） |

`file` = `{ file_path, file_name, mime_type, size_bytes }`。成功回 `{ success: true, data }`，失敗回 `{ success: false, error }`（中文訊息）。

## 語言與退回規則（公開頁）

`/m/<編號>?lang=ja` → 有日文就直接開；沒有就退回英文；仍沒有才顯示選擇頁。可用逗號指定順序，例如 `?lang=ko,ja`。`zh` 視為 `zh-TW`，不分大小寫。**沒帶 `lang` 且只有一份文件 → 直接開；多份 → 選擇頁。**
新增語言：在 `lib/mediaConfig.ts` 的 `MEDIA_LANGS` 加一行（資料庫不限制語言值）。目前支援 zh-TW、en、ja、ko、de、fr、zh-CN。

## 已驗證與未驗證

**本機模擬環境**（74 項，全部通過）：簽章驗證（錯誤、過期、舊憑證輪換）、建立／覆蓋／保留 3 版／還原／下架／刪除、重送請求被擋、語言退回、HTML 沙盒標頭、輸入注入字串被擋。

**真實專案冒煙測試**（2026-11-18，對 `gass-puce.vercel.app` 與真實 Supabase，35 項中 34 項通過；測試資料已清除）：
- 真實 Storage 的簽名上傳、簽名下載、列出、刪除都能用，檔案內容取回一致，原檔名下載正確（中文檔名也正確）
- 真實資料表的唯一限制、版本修剪（保留 3 版）、還原、下架、多語言與語言退回都正常
- bucket 是私有的：沒有簽名取不到、用 public 路徑也取不到
- 匿名（公開金鑰）讀取、寫入新資料表、呼叫計次函式，都被拒絕
- HTML 說明書帶沙盒標頭、沒有疊上本站 CSP
- 27MB 大檔案直傳約 2.4 秒、取回大小一致；超過 50MB 在發放通行證時就被擋

**已知限制（不是 bug，但要知道）**：Supabase Storage 前面有 CDN 快取。檔案被刪除或覆蓋修剪後，**已經發出去的簽名連結，在快取期間仍可能取到舊檔**（實測：刪除 3 秒後，同一連結仍回 200，`cf-cache-status: HIT`）。檔案在儲存空間裡確實已刪除（列出時找不到、無法再登記、也不會再發新連結）。影響：說明書本來就是公開內容，一般沒問題；**若誤傳了不該公開的檔案，刪除後不能假設立刻無法取得**。這與 ERP 現有行為相同，不是搬遷造成的。

**尚未驗證**：瀏覽器直傳到新專案（階段 3，ERP 端）；ERP 端改呼叫管理 API 後的完整後台操作。

## 切換步驟（階段 4）

**前提**：永久網域尚未決定（暫用 `gass-puce.vercel.app`）。切換後 ERP 的舊連結會轉址到 `PORTAL_PUBLIC_BASE`；之後換網域，只要改那一個環境變數。已印出去的 QR 指向 ERP 的 `/m/`，所以**不受網域變更影響**。

1. **凍結**：切換前，請所有人停止在 ERP 媒體庫上傳或覆蓋。
2. **補同步**：在本機執行 `node scripts/migrate-media-to-portal.mjs --dry` 看有沒有「待搬」（凍結期間新增的文件）；有就正式執行一次（已存在的會跳過）。若有人覆蓋過既有文件的內容，腳本不會補版本，需另外處理。再執行 `--sync` 校正開啟次數並核對內容。
3. **ERP 設定環境變數**（Vercel，ERP 專案，Production），然後重新部署：
   - `MEDIA_BACKEND` = `portal`
   - `PORTAL_ADMIN_URL`、`PORTAL_PUBLIC_BASE` = 保固網站網址
   - `PORTAL_ADMIN_SECRET` = 與保固網站相同的管理憑證
   - `PORTAL_SUPABASE_URL`、`PORTAL_SUPABASE_ANON_KEY` = 保固網站 Supabase 的網址與 publishable key（公開值）
   - 缺任何一個，ERP 都會自動維持舊行為並在 log 提醒，不會只切一半。
4. **驗證**：登入 ERP 媒體庫 → 看得到 21 份 → 上傳一份測試檔、覆蓋、下載、還原、刪除 → 開 `lemeng-erp.vercel.app/m/pencil-x?lang=en`，應轉址到保固網站並直接開英文版。
5. **保固網站**：`lib/portalConfig.ts` 的 `manualUrl` 改成同網站路徑（不再經過 ERP），推上去。
6. **退路**：把 ERP 的 `MEDIA_BACKEND` 刪掉或改成別的值並重新部署，即回到舊行為（ERP 舊資料在階段 5 之前都還在）。

## 階段 5（觀察一陣子之後）

確認沒問題後，才清除 ERP 專案裡的舊媒體資料（`media_files`、`media_versions`、bucket `manuals`）。**清除前務必先備份。**
